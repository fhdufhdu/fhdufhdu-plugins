# Wiki

## 시작

1. 먼저 같은 플러그인의 [init 스킬](../init/SKILL.md)을 읽고 실행해 환경이 구성됐는지 확인한다. init이 정상 종료하면 현재 요청을 계속한다. 환경이 미완료이면 그 문제를 먼저 해결하고, 완료되지 않은 상태로 위키를 수정하지 않는다.
2. 대상은 항상 `~/.fhdufhdu-wiki/wiki`다. 호출한 프로젝트의 `sources/`나 `pages/`와 혼동하지 않는다. 다른 디렉터리에서 호출해도 이 위키의 `AGENTS.md`/`CLAUDE.md`, `SCHEMA.md`, `PROJECT.md`, `INDEX.md`를 직접 읽어 적용한다. 기존 사용자 요청으로 승인된 범위는 반복 승인받지 않으며, 추가 승인이 필요한 변경은 구체적인 diff를 준비한 뒤 묻는다.
   세션 시작 동기화가 저장소 정책에 있으면 로컬 변경과 브랜치를 먼저 확인해 안전한 경우 `git pull --ff-only`한다. 분기·충돌·미커밋 변경은 강제로 해소하지 않는다. pull 후에는 인덱스를 재생성한다. `PROJECT.md`에 과거 기기의 절대 경로가 있어도 이 플러그인의 실제 클론 경로를 사용한다.
3. 사용자 의도를 **source 작성**, **기존 source 컴파일**, 또는 **작성 후 컴파일**로 구분한다. 기록만 요청했다면 source를 작성하고, 컴파일만 요청했다면 기존 원본을 사용한다.

아래 명령은 `--wiki-root`로 대상을 고정한다. `wwiki compile`이라는 CLI 명령은 없다. **컴파일은 에이전트가 원본을 읽어 구조화 페이지를 작성하는 작업**이다.

## Source 작성

1. 요청한 내용과 기존 `sources/`를 확인해 중복 기록인지 새 기록인지 판단한다. 사용자가 파일을 지정하면 그 파일을 사용한다. 그 외에는 저장소의 기존 날짜·파일명 규칙을 따른다.
   이 저장소는 업무/공부 각각 정리본과 스크래치패드를 구분한다. `PROJECT.md`의 현재 배치 규칙으로 위치를 정하고 정리본과 상세 스크래치패드를 모두 컴파일 대상으로 취급한다.
2. 사용자 메모·제공 자료를 `sources/` 아래 Markdown으로 작성한다. 사실, 결정, 이유, 미결 사항을 구별하고 URL·출처·날짜가 제공되면 보존한다. 제공되지 않은 사실을 채워 넣지 않는다.
3. 원본의 의미와 맥락을 보존한다. 기존 source 수정은 요청 범위에 한정하고, unrelated 메모를 교체하지 않는다. 컴파일을 요청받지 않았다면 `--mark-compiled`를 실행하지 않는다.
4. `wwiki sources --wiki-root "$HOME/.fhdufhdu-wiki/wiki"`로 새 기록이 `new` 또는 `changed`로 인식되는지 확인한다.

## Source → Wiki 컴파일

1. `wwiki sources --wiki-root "$HOME/.fhdufhdu-wiki/wiki"`로 `new`와 `changed` 원본을 확인한다. 사용자가 지정한 원본을 우선하고, 범위 지정이 없으면 미컴파일 델타를 대상으로 한다. 이미 `compiled`인 원본은 명시적인 재컴파일 요청이 있을 때만 처리한다. 삭제된 source는 페이지 자동 삭제의 근거로 삼지 않는다.
2. 대상 원본 전체를 읽고 `wwiki search "핵심어" --wiki-root "$HOME/.fhdufhdu-wiki/wiki"`와 기존 페이지를 확인해 새 페이지 또는 기존 페이지 병합을 결정한다. 기존 페이지를 갱신할 때 다른 원본에서 온 내용을 보존한다.
3. 저장소 스키마에 맞게 `pages/`의 구조화 페이지와 `INDEX.md` 변경을 준비한다. frontmatter의 제목·생성일·수정일·confidence·sources·related·tags·status 등은 실제 스키마를 따른다. source 출처는 `[[sources/...]]`, 하위 페이지 링크는 `[[infra/db]]`처럼 경로를 포함한다. 추정과 사실을 구분하고 모순은 기존 정보를 삭제하는 대신 근거와 함께 명시한다.
4. 요청 범위와 저장소의 승인 규칙에 따라 변경을 적용한다. 원본 source는 삭제하거나 컴파일 결과로 덮어쓰지 않는다. 승인 대기·부분 실패인 변경을 처리 완료로 표시하지 않는다.
5. `wwiki reindex --wiki-root "$HOME/.fhdufhdu-wiki/wiki"`와 `wwiki lint --wiki-root "$HOME/.fhdufhdu-wiki/wiki"`를 실행한다. lint는 JSON 내용을 읽어 판단한다(종료 코드만으로 통과를 판단하지 않는다). 이번 변경으로 생긴 깨진 링크·모호한 링크·잘못된 출처를 고친다. 기존 위생 경고는 이번 변경과 구분해 알린다. 페이지를 다시 고쳤으면 인덱스도 갱신한다.
6. 해당 원본의 페이지·인덱스 반영과 검증이 성공한 뒤에만 실행한다. 직전에 `wwiki sources`를 다시 실행해 원본 해시를 갱신하고, 출력의 경로 문자열을 그대로 인자로 전달한다. 한글 경로를 다시 타이핑하거나 Unicode 정규화를 바꾸지 않는다. 원본 내용이 페이지 작성 이후 바뀌었다면 새 내용을 반영하기 전까지 완료 표시하지 않는다. 여러 원본 중 일부만 성공했다면 성공한 경로만 넘긴다.

   ```bash
   wwiki sources --wiki-root "$HOME/.fhdufhdu-wiki/wiki" --mark-compiled sources/실제로-처리한-원본.md
   ```

7. `marked_compiled` 수가 요청한 원본 수와 같은지, `unmatched`가 없는지 확인하고, `wwiki sources`로 완료 상태를 재확인한다. 종료 코드가 0이어도 표시 수가 부족하면 실패로 취급한다. 마지막으로 `wwiki reindex`와 `wwiki lint`를 실행해 미컴파일 항목을 포함한 최종 상태를 확인한다. 실패 시 수정한 파일과 아직 처리하지 못한 원본을 구분해 보고하고 다음 실행에서 이어간다.

## 마무리

작성·수정한 source와 페이지의 실제 파일 링크, 컴파일한 원본, 남은 경고를 짧게 알린다. Git 커밋·push는 사용자 요청이나 명시적인 저장소 정책이 있을 때 수행한다. source 작성·컴파일 요청만으로 원격 게시를 추가하지 않는다.
