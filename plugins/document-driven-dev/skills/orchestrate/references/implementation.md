# 구현 에이전트 전달과 상위 검토

## 위임 전 확인

- 실행 모드에서 구현이 허용되어 있는지 확인한다.
- 해당 태스크의 선행 작업과 공통 계약이 준비되었는지 확인한다.
- 파일 범위가 다른 진행 중 태스크와 충돌하지 않는지 확인한다.
- 진행 인덱스를 진행 중으로 갱신하고 결과 문서 경로를 준비한다.

독립 태스크는 환경의 동시 실행 한도 내에서 병렬 위임할 수 있다. 같은 파일을 수정하거나 선행 결과에 의존하는 태스크는 순차 실행한다. 프로젝트별 모델 선택이 있으면 실행 설정에 반영한다. 설정 변경을 프롬프트 역할명으로 대신하지 않는다.

## 전달 지시문

다음 내용을 실제 태스크에 맞춰 전달한다. 경로는 하위 에이전트가 접근할 수 있는 정확한 경로를 사용한다.

```markdown
너는 상위 아키텍트가 확정한 태스크의 구현과 검증을 담당한다.
이번 작업의 파일 범위, 공개 계약, 완료 기준을 준수하라.

입력 자료:
- 프로젝트 및 적용 지침 경로
- 태스크 명세 경로
- 공통 계약 경로와 읽을 항목
- 참고할 기존 코드와 선행 태스크 결과
- 작성할 결과 문서 경로

작업 규칙:
1. 입력 자료와 관련 코드를 읽고 지정 범위를 구현한다.
2. 기존 라이브러리·공통 코드·스타일을 우선 사용한다.
3. 계약과 제품 동작을 임의로 변경하지 않는다. 충돌이 있으면 영향과 필요한 결정을 상위에 보고한다.
4. 요청 범위 밖 리팩터링·기능·의존성을 추가하지 않는다.
5. 사용자와 다른 담당자의 변경을 덮어쓰지 않는다.
6. 요구 동작을 TODO, 빈 함수, 임시 mock, 하드코딩된 성공 응답으로 대체하지 않는다. 명세가 허용한 mock은 예외다.
7. 사소한 구현 선택은 기존 관례에 맞춰 해결한다. 정확한 구현을 막는 누락은 추측하지 않고 기록하며 독립 작업은 계속한다.
8. 지정 코드와 자기 결과 문서만 수정한다. 진행 인덱스와 공통 계약 변경은 상위 담당자에게 요청한다.

검증과 결과:
- 명세의 검증과 변경에 필요한 프로젝트 필수 검사를 실행한다.
- 이번 변경에서 발생한 실패는 수정하고 재검증한다.
- 실제 실행 결과와 코드 검토로 확인한 내용을 구분한다.
- 실행하지 못한 검증은 미실행과 이유를 기록한다.
- 결과 문서에 변경 파일, 완료 기준별 충족 여부, 검증 결과, 차단 사항, 후속 영향을 기록한다.
- 완료 기준을 충족하지 못했다면 완료로 보고하지 않는다.
- 내부 추론 대신 결과와 검증 근거를 보고한다.

최종 응답은 검토 요청 / 부분 완료 / 차단 중 현재 구현 상태,
결과 문서 경로, 검증 요약, 남은 사항으로 정리한다.
```

결과 문서 형식은 태스크 자료에 포함하거나 [문서 형식](documents.md)의 `results/Txx-result.md` 항목을 읽도록 지정한다. 구현 중 공통 계약 변경이 필요하면 Sol이 결정 기록·기준 계약·관련 태스크를 먼저 갱신한 뒤 새 지시를 전달한다.

## 위임 기능이 없는 환경

현재 에이전트가 동일한 태스크 경계와 검증 기준에 따라 구현한다. 결과에 실제 담당과 위임 불가 사유를 기록한다. 특정 모델 사용이 필수인 요청을 조용히 다른 모델로 대체하지 않는다.

파일 편집 도구가 없다면 경로별 전체 코드와 결과 문서를 제공하고 저장·실행하지 못했음을 기록한다. 실제로 수정하지 않은 파일을 수정했다고 보고하지 않는다.

## 상위 검토와 완료 처리

Sol은 담당자의 요약뿐 아니라 실제 코드 변경과 결과 문서를 읽는다.

1. 요청된 범위, 기존 동작 보존, 공개 계약 준수 여부를 검토한다.
2. 정상·경계·오류 사례와 완료 기준별 근거를 확인한다.
3. 검증이 실제 수행되었는지 확인하고 필요한 누락 검증을 실행한다.
4. 결함은 같은 태스크에 보완 지시하거나 의존성이 명확한 보완 태스크로 만든다.
5. 결과 문서의 상위 검토를 기록하고 진행 인덱스를 완료 또는 차단 등 실제 상태로 갱신한다.

담당자 보고가 도착하면 검토 대기로 표시한다. 선행 작업 완료를 기다리는 계획 태스크와 외부 결정 때문에 차단된 태스크를 구분한다. 필수 검증이 실패·미실행이면 완료 처리하지 않는다.

태스크가 완료된 뒤 검증을 이유 없이 반복하지 않는다. 새 변경이나 통합 결함이 기존 결과에 영향을 주면 관련 검증을 다시 실행한다. 모든 구현 태스크 후에는 전체 사용자 흐름과 회귀 검증을 수행하고 통합 검토 문서에 기록한다.
