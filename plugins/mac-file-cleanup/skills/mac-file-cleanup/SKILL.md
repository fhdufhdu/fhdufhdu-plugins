# Mac 파일 정리

Mole이 제시하는 정리 후보와 사용자가 지정한 파일의 정리 계획을 다룬다. 용량을 확보하려는 요청에는 다시 만들기 쉬운 후보부터 살펴보고, 목표 용량이 있으면 그 목표에 필요한 범위까지만 제안한다.

## 요청에 맞게 살펴보기

- 저장 공간이 부족하면 `df -h /`로 여유 공간을 확인하고 `mo analyze --json`으로 큰 위치를 찾는다. 경로가 주어지면 `df -h "$target"`, `mo analyze --json "$target"`처럼 해당 위치부터 확인한다. JSON 플래그는 경로 앞에 둔다. 상위 폴더와 그 안의 항목을 합산하지 않는다. 분석 용량은 사용량으로, 실제 회수 가능량은 정리 미리보기의 추정치로 표시한다.
- 캐시, 로그, 임시 파일, 이미 제거한 앱의 잔여 파일까지 Mac 전반에서 살펴보라는 요청에는 `mo clean --dry-run`을 사용한다. 실행 요약과 이번 실행이 만든 `~/.config/mole/clean-list.txt`를 확인한다. 미리보기는 파일 삭제 없이 후보 목록이나 로그를 기록할 수 있다. 후보 목록이 생성되지 않았거나 오래된 경우에는 해당 목록을 이번 결과로 사용하지 않는다.
- 설치 파일 또는 프로젝트 빌드 산출물을 Mac 전반에서 정리하려는 요청에는 각각 `mo installer --dry-run`, `mo purge --dry-run`을 사용한다. `purge`는 지정된 검색 루트를 사용하므로 현재 루트를 도움말과 기존 설정에서 확인한다. 폴더나 프로젝트가 지정되면 해당 경로의 메타데이터를 직접 확인한다. 디렉터리 이름만으로 재생성 가능하다고 판단하지 않는다. 추적 중인 파일, 작업 중인 프로젝트, 다시 내려받는 데 시간이 드는 의존성은 따로 표시한다.
- 다운로드, 바탕화면, 특정 폴더 정리는 [폴더 정리](#폴더-정리) 절차를 따른다. 파일 이동만 요청했으면 캐시 정리로 범위를 넓히지 않는다.

Mole을 처음 사용할 때 로컬 macOS 여부와 `mo --version`을 확인한다. 플래그나 출력이 다르면 설치된 CLI의 `mo <command> --help`를 따른다. 구버전 JSON에는 `scan_status`나 `large_files`가 없을 수 있다. 확인된 `partial`은 하한값으로, `unavailable`은 미측정으로 보고한다. 권한 오류와 타임아웃도 적용 범위에 명시한다. `mo`가 없거나 분석이 막히면 `df`와 macOS `du -k -x -d 1 "$target"` 등으로 요청 범위를 읽기 전용으로 확인한다. CLI 설치와 업데이트는 사용자가 요청한 경우에만 한다.

## 폴더 정리

1. 지정한 경로에서 파일명, 유형, 크기, 수정일 등 필요한 메타데이터만 살펴본다. 우선 바로 아래 항목을 확인하고, 요청에 필요한 하위 폴더만 탐색한다. 심볼릭 링크를 따라가거나 앱 패키지 내부를 탐색하지 않는다. 클라우드 동기화 폴더는 요청 범위에 있을 때만 살펴보며 온라인 전용 파일을 강제로 내려받지 않는다.
2. 사용자의 분류 기준에 따라 원본 경로와 목적지 경로를 계획한다. 분류 기준이 없으면 파일 형식이나 날짜처럼 메타데이터로 판단할 수 있는 기준을 제안한다. 대용량이나 오래된 파일은 검토 후보로 표시한다. 중복 확인을 요청한 경우 같은 크기의 로컬 일반 파일부터 비교하고, SHA-256이 같은 후보만 `cmp`로 확인한다. 같은 inode를 가리키는 하드 링크는 별도 용량을 차지하는 복사본으로 계산하지 않는다. 어떤 복사본을 보관할지는 경로와 용도를 보고 정한다.
3. 이동이나 휴지통 처리를 이미 구체적으로 지시한 경우에는 그 범위대로 진행한다. 그 외에는 정확한 원본·목적지 또는 휴지통 후보를 먼저 보여 주고 사용자 선택을 받는다. 실행 직전에 경로와 파일 정보가 그대로인지 확인하고, 목적지에 같은 이름이 있으면 해당 항목을 건너뛴다. Finder 등에서 덮어쓰지 않는 이동이나 macOS 휴지통 기능을 사용한다. 보호 경로, 심볼릭 링크를 경유하는 경로, 권한으로 차단된 경로는 건너뛴다.
4. 처리 후 원본과 목적지를 확인하고 성공·건너뜀·실패 건수를 알려 준다. 휴지통으로 옮긴 용량은 실제로 확보된 디스크 공간으로 계산하지 않는다.

## Mole 미리보기와 실행 범위

- 예상 회수량, 큰 후보, 재다운로드나 재빌드가 필요한 항목, 미측정 범위를 요약한다. 개인 파일명은 사용자가 그 파일을 검토해 달라고 한 경우나 승인에 필요한 경우에만 보여 준다.
- `mo clean`, `mo purge`, `mo installer`의 실제 실행은 영구 삭제할 수 있다. `clean`은 설정에 따라 기존 휴지통을 비울 수 있고, 미리보기 뒤에 다시 스캔한다. 실제 후보를 미리 확인한 경로에 고정할 수 없으므로 에이전트는 이 세 명령을 미리보기로 사용한다. 사용자가 영구 정리를 원하면 미리보기 결과와 함께 해당 Mole 명령의 범위, 휴지통 포함 여부, 선택 화면의 유무를 안내한다. 일부 파일만 처리할 때는 검토된 개별 경로를 휴지통으로 옮기는 방식을 사용한다. Mole이 건너뛰거나 보호한 항목은 직접 삭제하는 방식으로 우회하지 않는다.
- 사용자가 보호할 경로를 지정하면 `mo clean --whitelist`를 안내한다. 설정을 변경한 뒤 새 미리보기에서 보호 여부를 확인한다. 기존 보호 목록을 덮어쓰거나 관리자 권한을 요청해 범위를 넓히지 않는다.
