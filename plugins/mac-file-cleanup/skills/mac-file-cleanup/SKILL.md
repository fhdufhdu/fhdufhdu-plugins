# Mac 파일 정리

로컬 macOS에서 실행한다. `df`, `du`, `find`, `stat`, Finder 등 기본 도구로 조사하고, [후보 선별과 보호 규칙](references/candidates.md)을 적용한다. 개발 도구·가상머신·패키지 캐시는 [개발 도구와 대용량 앱 데이터](references/dev-tools.md)를 따른다. 후보를 조사할 때는 파일을 수정하지 않는다.

## 도구 사용 주의

- 사용자 셸에서 `find`, `du`, `ls`, `rm`이 `bfs`, `dust`, `eza`, `trash` 같은 대체 도구로 alias되어 있을 수 있다. 조사와 검증에는 `/usr/bin/find`, `/usr/bin/du`, `/usr/bin/stat`처럼 절대 경로를 쓴다. 예를 들어 `bfs`는 `-newermt '7 days ago'`를 해석하지 못해 최근 활동 검사가 오류로 끝난다.
- `~/Library/Caches` 같은 큰 폴더를 측정할 때 하위 항목별 `du -s`를 한 번에 실행하고 크기순으로 정렬한다. 홈 전체를 한 번에 `du`하지 않는다.

## 조사 범위 정하기

- 저장 공간이 부족하면 여유 공간을 **데이터 볼륨**에서 확인한다. APFS에서 `/`는 읽기 전용 시스템 볼륨이라 `df -k /`의 사용률이 실제보다 낮게 보인다(예: `/` 67%, 데이터 볼륨 99%). `df -h /System/Volumes/Data`의 `Avail`을 기준값으로 기록한다.
- Mac 전반의 후보를 묻는 경우 아래 위치를 하위 항목별로 측정해 큰 순서대로 살펴본다. 존재하지 않거나 심볼릭 링크인 위치는 건너뛴다.
  - `~/Library/Containers`, `~/Library/Caches`, `~/Library/Application Support`, `~/Library/Developer`, `~/Library/Logs`
  - `~/Downloads`, `~/Desktop`, `~/Documents`, `~/Movies`, `~/Pictures`
  - `~/.gradle`, `~/.m2`, `~/.npm`, `~/.cache`, `~/.local`, `~/.rustup`, `~/.cargo`, `~/.nvm`, `~/.sdkman`, `~/.pyenv`, `~/.ollama`
  - 사용자가 알려 준 프로젝트 루트(예: `~/project`, `~/code`). 프로젝트 산출물은 사용자가 지정한 루트에서만 확인한다.
- 큰 항목은 한 단계씩 내려가며 원인을 좁힌다. 앱 데이터(`Containers`, `Application Support`)는 원인 파악까지만 하고, 정리는 [개발 도구 가이드](references/dev-tools.md)의 도구 명령이나 사용자 판단으로 넘긴다.
- 경로가 지정되면 그 위치의 바로 아래부터 확인한다. 필요한 하위 폴더만 더 살펴보고, 시스템 전반 정리로 범위를 넓히지 않는다. 용량 목표가 있으면 다시 만들기 쉬운 후보부터 순위를 매겨 목표에 필요한 범위로 좁힌다.
- 관련 앱이나 빌드가 실행 중인지 `pgrep -lf`로 확인하고 미리보기에 적는다(Docker, IDE, Xcode, `cargo`, `gradle` 데몬, 브라우저 다운로드 등).
- 탐색 결과는 파일명, 유형, 할당량, 수정일 등 필요한 메타데이터를 중심으로 작성한다. 중복 확인을 요청한 경우 로컬 일반 파일을 크기로 먼저 묶고, 같은 크기에서만 SHA-256을 비교한 뒤 해시가 같은 파일을 `cmp -s`로 검증한다. 동일 장치·inode를 공유하는 하드 링크는 별도 복사본으로 계산하지 않는다.
- 여러 프로젝트의 빌드 산출물은 [scan-build-artifacts.sh](scripts/scan-build-artifacts.sh)로 한 번에 판정할 수 있다. 읽기 전용이며 `OK`, `RECENT`, `NO_MANIFEST` 등 판정을 TSV로 출력한다.

## 미리보기 만들기

각 후보의 정확한 경로, 유형, 디스크 할당량, 선정 근거, 복구 또는 재생성 비용을 표에 적는다. 폴더 분류 요청에는 원본과 목적지를 보여 준다. 요청에서 지정한 보호 경로와 그 하위 항목을 제외하고, 후보 폴더 안에 보호 경로가 있는 경우 그 폴더도 통째로 옮기지 않는다.

후보는 세 묶음으로 나눠 번호를 붙인다. 사용자가 "A 전부, 8번"처럼 골라 답할 수 있게 한다.

1. **바로 정리 가능**: 재생성할 수 있고 사용 중이 아님이 확인된 항목. 묶음 합계를 적는다.
2. **사용자 판단 필요**: 업무 파일, 가상머신, 의존성 캐시, 진행 중일 수 있는 다운로드, 최근 수정된 대형 산출물 등.
3. **건너뜀**: 최근 수정, 매니페스트 없음, Git 추적 등 제외 이유와 함께 묶어서 적는다.

처리 방식도 함께 적는다. 휴지통 이동인지, 도구 명령(`docker system prune`, `cargo clean` 등)으로 **즉시 삭제**되는지 구분한다.

근거가 충분한 후보, 사용자가 판단해야 할 파일, 누락된 범위를 표시한다. 보호 대상이라 측정만 하고 건드리지 않은 큰 위치(예: 브라우저 프로필, 앱 데이터)도 한 줄로 알린다. 권한 오류와 중단된 검사는 미측정으로 기록한다. 상위 폴더와 그 안의 항목 및 동일 장치·inode를 중복 합산하지 않는다. `du`의 할당량은 후보 크기 추정치다. APFS 스냅샷, 클론, 하드 링크 때문에 실제 여유 공간 증가는 다를 수 있다.

## 선택한 항목 처리하기

1. 미리보기만 요청한 경우 결과를 전달하고 마친다. 목록이 여러 항목이거나 범위가 포괄적이면 정확한 경로를 제시하고 사용자의 선택을 받는다. 사용자가 이미 정확한 원본과 작업을 지시했다면 그 범위에 적용한다.
2. 실행 직전에 승인된 경로의 포함 범위와 소유권, 심볼릭 링크 여부, 보호 규칙을 다시 확인한다. 미리보기에서 기록한 장치·inode·유형·크기·수정 시각과 달라졌거나 하위 활동을 재검증할 수 없는 항목은 건너뛴다. 새로 발견한 항목은 기존 선택에 포함하지 않는다. 이동 대상에 이름 충돌이 있으면 해당 항목을 건너뛴다. 마운트된 디스크 이미지는 먼저 꺼낸다.
3. 선택한 항목만 휴지통으로 보낸다. macOS 14 이상은 `/usr/bin/trash -v <경로>...`를 쓰고, 없으면 Finder(`osascript -e 'tell application "Finder" to delete POSIX file "<경로>"'`)를 쓴다. 항목마다 성공·실패를 기록한다. 폴더 분류에는 덮어쓰기 없는 이동(`mv -n`)을 사용한다. 휴지통을 비우거나 관리자 권한으로 진행하지 않는다. 도구 정리 명령은 사용자가 그 명령을 승인한 경우에만 실행한다.
4. 원본과 이동 목적지 또는 휴지통 처리 결과를 확인한다. 성공·건너뜀·실패 건수와 대표 경로를 보고한다. 휴지통으로 이동한 크기는 처리 규모로 표시한다.
5. 데이터 볼륨의 여유 공간을 `df -h /System/Volumes/Data`로 다시 재고 시작 값과 비교한다. **휴지통으로 옮긴 용량은 휴지통을 비우기 전까지 회수되지 않는다.** `/usr/bin/du -sh ~/.Trash`로 휴지통 크기를 함께 알리고, 비우기는 사용자가 Finder에서 직접 하도록 안내한다. 정리한 산출물을 다시 쓸 때 필요한 명령(`npm install`, `gradle build`, `uv sync` 등)도 한 줄로 알린다.
